# 最终验收标准与不通过时的修法（一次性交付口径）

> 目标：全部阶段（三/四/六/五）完成后，用本文件逐条自验；
> 不通过的就地修，**不允许调低阈值、跳过用例、删测试来"通过"**。
> 结果写成 `docs/ACCEPTANCE-REPORT.md` 并 push。

---

## 0. 我们要达成的目标（一句话）

```
一个私有素材库：传得进（4K@60、≤2GB、可续传）、播得出（自动转码成 30fps 变体）、
打不挂（公开读 0 数据库）、看得住（巡检/备份/额度告警）。
插件不改代码即可正常读取与播放。
```

## 8. 不通过怎么办（固定流程，不许绕）

```
1) 定位根因（不是先改测试）：
   · 数据层：查 D1 该条实际值（status/variants/needs_variant/is_public 分类）
   · 快照层：看 snapshots/<version> 文件是否存在、内容是否含该条
   · 代码层：读路径是否走了快照、DTO 是否丢字段
2) 写一条能复现该问题的测试（先红）
3) 修代码到测试绿
4) 重跑该组全部检查（不是只跑那一条）
5) 把「问题 → 根因 → 修法 → 复测结果」写进 docs/ACCEPTANCE-REPORT.md
6) 同一项连续两次修不好 ⇒ 停下来写报告（现状/两个方案/代价），不要继续堆补丁
```

**明确禁止的"假通过"**

```
· 调大阈值/放宽断言（例如把"行读≈0"改成"≤1000"）
· 跳过/删除失败的测试
· 只贴本地测试、不贴线上证据
· 把 degraded 当正常（degraded 必须能说明原因）
```
